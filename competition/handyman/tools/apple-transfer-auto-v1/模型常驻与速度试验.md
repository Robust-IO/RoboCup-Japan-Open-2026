# 模型常驻与导航速度试验

2026-10-26：保留原模型权重，复用已预热的模型进程，并按用户要求试验新的导航速度档。

## 实际配置

| 项目 | 原 `balanced_v1` | 新 `carry_fast_v1` |
| --- | --- | --- |
| 空载长路段直线速度上限 | 0.28 m/s | 0.28 m/s |
| 持物长路段直线速度上限 | 0.24 m/s | 0.28 m/s |
| 空载转向上限 | 0.4 rad/s | 0.8 rad/s |
| 持物转向上限 | 0.3 rad/s | 0.8 rad/s |
| 不超过 1.6 m 的短路段直线上限 | 0.2 m/s | 0.2 m/s |
| 短路段转向上限 | 0.2 rad/s | 0.8 rad/s |

这是速度上限，实际速度仍由 Nav2 依据路径、加减速度和当前位置确定。机械臂速度、近桌有限位移速度、路线、地图、目标误差和加减速度没有修改。Unity 项目自身的底盘上限为 0.3 m/s、1.1 rad/s，本次试验无需修改 Unity。

配置文件为 `config/motion_speed_profiles.json`。`config/apple_transfer_auto_v1.json` 中的 `navigation_motion_profile` 选择新导航档，`motion_profile` 仍为 `balanced_v1`，用于保持机械臂与有限位移行为。

企鹅/胡椒入口可以显式回退导航速度：

```bash
./run_object_transfer.sh --object toy_penguin --run \
  --confirm-layout LayoutA --confirm-localization --simulation-ignore-collision \
  --navigation-profile balanced_v1 --output /__HANDYMAN_PACKAGE__/runtime/一个全新目录
```

运行前应确认物品实际所在家具和当前机器人状态，不能直接重放已经闭爪或松爪的旧任务。

## 模型常驻

`run_object_transfer.sh` 默认设置 `HANDYMAN_RESIDENT_MODEL=1`。`apple_worker_client.Worker` 连接 `resident_inference.py` 管理的本地服务；服务沿用原有 `apple_shared_inference.py`、`apple_inference_worker.py`，不改变检测算法或权重。

每次任务客户端结束只断开连接，模型仍保留。每次请求读取该次捕获的 RGB、深度和时间戳，不缓存旧检测结果或旧任务坐标。原有图像新鲜度和身份核对条件保留。

模型 SHA、注册表、Python、推理代码版本、输入分辨率和 ROI 选项共同决定服务键。640 和 960 输入可以对应不同常驻进程。注册表发生变化时，已连接客户端拒绝继续使用旧上下文。

IPC 位于 `/tmp/hm-resident-1000/`，仅限本机用户；日志和启动记录保存在 `D:\handyman-training-runs\resident-model\`。关闭任务不会退出模型，关闭系统会退出。修改模型或推理代码后可能产生新服务，维护时根据对应 `launch.json` 核对并关闭旧服务，不能批量终止 Python/ROS 进程。

需要临时使用原来的独立加载模式时：

```bash
HANDYMAN_RESIDENT_MODEL=0 ./run_object_transfer.sh ...
```

- 第二个客户端连接：0.079 秒，同一模型 PID 27511。

证据为 `resident-model-benchmark-20261026-01.json`。回放结果不作为当前现场观测，也不用于证明某次抓取成功。

## 配套修复与验证

企鹅检测框内的远处垃圾桶曾进入高度前景，导致水平外沿误算为约 0.315 m。改为以实测身体和头部表面为种子，只连接图像相邻且三维连续的深度点；没有按尺寸上限截断结果。6 张先前失败的真实图像回放后外沿约 0.070 m，原有参考校验通过。

部署前完整回归 722 项通过，三个运行目录校验一致。新速度完整搬运试验目录为 `penguin-resident-fast-transfer-20261026-01`。最终结果已确认一次无中断完整搬运成功；闭爪 1 次、松爪 1 次，两个导航段均无反馈恢复重试，最终机器人空手收臂，企鹅位于客厅矮桌。

## 本轮完整实测结果

从初始位置出发，全程 424.700 秒，约 7 分 5 秒：

| 阶段 | 耗时 |
| --- | --- |
| 前往卧室 | 146.813 秒 |
| 目标检测与源端三帧定位 | 1.482 秒 |
| 展臂、接近、抓取验证与收臂 | 52.532 秒 |
| 持物前往客厅 | 174.199 秒 |
| 放置、退后收臂和最终验证 | 42.669 秒 |
| 预检与头部朝向等 | 约 7 秒 |

本任务确实复用 PID 27511 的模型，连接记录约 0.026 秒（另一次独立客户端基准含完整校验耗时 0.079 秒）。最终三帧均重新测得实际身体与头部深度，不使用持物过程中的运动学估计宣告放置成功。

两段导航实际应用了 `.28/.28/.8` 和短路段 `.2/.2/.8`，结束后均恢复原参数。因此静止时看到 `.2/.2/.2` 属于正常恢复行为。

模型常驻显著减少重复加载。新导航上限在本轮完成搬运，但**尚未证实能缩短导航时间**：空载约 147 秒、持物约 174 秒，没有优于以往记录。此前记录的物品与动态场景不同，不能直接算成严格 A/B 结论。原 `balanced_v1` 保留供后续同条件比较。
