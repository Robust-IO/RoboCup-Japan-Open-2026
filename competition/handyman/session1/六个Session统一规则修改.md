## 家具观察与抓取位姿

先使用当前位置的视角；失败后依次平视、俯视30°和较低视角。仍失败时，在同一房间、地图可达条件下，向原观察点左右约20厘米的新视角补看，始终面向指定家具。

识别后先检查当前实测点云中的局部抓取、臂长与抬臂/展臂/下降夹爪路径。可直接抓就不绕行家具。否则先选正对家具边、能覆盖目标的位姿；检查实测障碍，向更空的一侧偏移，偏角限制15°。到位重新测量；仍有干涉时按15°、10°、5°递减或换另一侧候选。

虚拟位姿点云仅用于筛选，不把预测当成已经到位的实测证据。碰撞检查依赖可见点云与现有手部模型，不声称具有遮挡后环境的完整几何。连续失败的抓取导航候选会退出当前候选并尝试下一候选；不再无限重复一个失败目标。

## 形状抓取

- 圆柱／类圆柱：优先身体截面；横躺时使用观测到的主轴。
- 球形：优先球心所在直径附近的接触区域。
- 不规则物品：候选必须存在观测到的明显凸起，顶端到根部的保守长度至少 **0.01m**。根部由相连窄截面向宽主体的过渡识别；无法观测根部不能假装测到了凸起长度。
- 上窄下宽瓶子：优先实际观测到的窄颈，不按历史坐标指定抓点。
- 保留实际局部夹持宽度、接触材料、接近路径与抓稳检查；形状偏好不替代这些物理条件。

当前已有桶口来自人工核对 RGBD 的数据，本次没有伪造新桶口，也没有运行 Unity 编辑器重导几何。若实际桶口有偏差，可用更新包中的工具单独导出内沿。

### 内沿导出工具

将更新包 `Assets/HandymanMapExporter/Editor/HandymanContainerOpeningWindow.cs` 放到 Unity 对应目录。工具只读取网格，不改比赛场景、材质或已有导出器。

1. 菜单 `Tools > Handyman Map Exporter > Export Container Inner Opening`。
2. 选择真实垃圾桶模型，填写精确的 `destination_id`（含 `#room`）。
3. 点击 Read vertices，开启 Pick inner rim，在 Scene 视图按顺序选择**内沿**网格顶点，至少4点。绿色轮廓应表示真实可投放开口，不是外包围盒。遮挡时旋转 Scene 视角检查。
4. Export 输出 JSON。坐标与原导出器一致：Unity `(x,y,z)` 转 ROS `(z,-x,y)`；最高选中点确定桶沿高度。
5. 在 Ubuntu 导入对应配置，例如：

```bash
cd /__HANDYMAN_PACKAGE__/workspace/training/session1
python3 import_container_opening.py --opening /__HANDYMAN_PACKAGE__/maps/export/container-inner-opening.json --config session2-live-config.json
```

Session4 使用 `session4-live-config.json`。导入会校验边界顺序、面积、目的地和旧坐标差异，并另存配置备份。无需重新生成整个占据地图；若整张地图坐标系改变，仍须走完整地图导入。
